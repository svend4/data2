## ПРЕДИСЛОВИЕ

Компания движется. Решения движутся по иерархиям. Информация движется между командами. Стратегия движется во времени.

Это не метафора. Это **буквальное описание организации как динамической системы** в информационном пространстве.

Именно поэтому законы движения Крюкова — петли, три сферы, резонанс, нечётность — применимы к организациям напрямую. Они описывают не только физическое движение тела, но **любое управляемое движение в сложной среде**.

Организация, которая движется «прямолинейно» — без петель обратной связи, без иерархической синхронизации, без резонанса уровней — неизбежно движется к стагнации или хаосу. Ровно как рука без петлевых траекторий — к травмам и скованности.

Этот том создаёт новый язык для описания организационных процессов — точный, формализованный и практически применимый.

### Глава 1. Организация как Динамическая Система

#### 1.1 Три Сферы Организации

Иерархия трёх сфер Крюкова точно соответствует стандартным уровням управления:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
БВС — БОЛЬШАЯ ВНЕШНЯЯ СФЕРА: Стратегический уровень
  Временной горизонт: 1–5 лет
  Участники: CEO, совет директоров, C-level
  Движение: позиционирование на рынке, M&A, продуктовые эпохи
  Метрики: доля рынка, EBITDA, brand equity, NPS (корпоративный)
  Аналог в боевом искусстве: движение всего тела в пространстве

СВС — СРЕДНЯЯ ВНУТРЕННЯЯ СФЕРА: Тактический уровень
  Временной горизонт: 1–12 месяцев
  Участники: VP, директора, руководители отделов
  Движение: проекты, кварталы, продуктовые циклы
  Метрики: OKR, sprint velocity, conversion rates, NPS продукта
  Аналог в боевом искусстве: движение предплечья (рычаг, усиление)

МВС — МАЛАЯ ВНУТРЕННЯЯ СФЕРА: Оперативный уровень
  Временной горизонт: дни–недели
  Участники: тимлиды, менеджеры проектов, исполнители
  Движение: задачи, тикеты, daily standups
  Метрики: velocity, lead time, CSAT, SLA compliance
  Аналог в боевом искусстве: движение кисти (точность, контакт)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 1.2 Петля как Организационная Обратная Связь

В системе Крюкова **петля** — это замкнутое движение с обратной связью. В управлении это прямое соответствие **контурам обратной связи**:

```
ПЕТЛЯ УПРАВЛЕНИЯ (управленческая петля):

Планирование → Исполнение → Измерение → Анализ → Корректировка
      ↑___________________________________________________|

Это петля! Замкнутая траектория в «пространстве решений».

Признаки ХОРОШЕЙ организационной петли:
  1. Замкнутость: всегда есть возврат (ретроспектива, отчёт)
  2. Ритмичность: петля повторяется с постоянной частотой
  3. Амплитуда адекватна задаче (не слишком мало, не слишком много)
  4. Один оборот = один цикл принятия решения

Признаки ПЛОХОЙ петли (организационная патология):
  ✗ Разорванная петля: «решение принято — никто не проверил результат»
  ✗ Неритмичная петля: совещания «когда успеем»
  ✗ Нулевая амплитуда: формальные отчёты без реальных изменений
  ✗ Бесконечная петля: «ещё один раунд анализа» без решения
```

**Loop Closure Index для организации:**

```python
def org_lci(meeting_records):
    """
    Вычислить LCI для организационных процессов.

    LCI = решения_с_контролем_исполнения / все_решения

    LCI > 0.8 — здоровая петлевая культура
    LCI < 0.5 — «решения без ответственности» (патология)
    """
    total_decisions = 0
    decisions_with_followup = 0

    for meeting in meeting_records:
        for decision in meeting.decisions:
            total_decisions += 1
            if decision.has_owner and decision.has_deadline and decision.was_reviewed:
                decisions_with_followup += 1

    if total_decisions == 0:
        return 0.0
    return decisions_with_followup / total_decisions
```

#### 1.3 Резонанс Организации

Условие резонанса из системы Крюкова: `ω_МВС = ω_СВС = ω_БВС → РЕЗОНАНС`

В организационном контексте:

```
РЕЗОНАНС ОРГАНИЗАЦИИ =
  «Стратегия (БВС), тактика (СВС) и операции (МВС) синхронизированы»

Признаки резонанса:
  ✓ Тимлид понимает, как его sprint-задачи влияют на квартальный OKR
  ✓ Квартальные OKR понятно связаны со стратегией на 3 года
  ✓ Когда стратегия меняется — операции подстраиваются за дни, не за кварталы
  ✓ Нет «разрывов перевода»: стратегический язык и операционный язык совпадают

Антирезонанс (дисфункция):
  ✗ Стратегия: «станем лидером по инновациям»
     Тактика:   «KPI — число выпущенных фич»
     Операции:  «делаем то, что быстрее всего закроет тикет»
  → Три уровня движутся в разных ритмах = организационный хаос

Теорема резонанса:
  Организация достигает пиковой эффективности тогда и только тогда,
  когда информация, метрики и ценности синхронизированы между всеми
  тремя уровнями иерархии.
```

**Индекс Резонанса Организации (ИРО):**

```python
def org_resonance_index(strategy_goals, tactical_okrs, operational_metrics):
    """
    Измерить синхронизацию трёх уровней организации.

    Возвращает: ИРО ∈ [0, 1]
    0 — полная десинхронизация
    1 — полный резонанс
    """
    # Трассируемость: можно ли проследить от операции до стратегии?
    traceability_score = 0
    operational_items = operational_metrics.items

    for op_item in operational_items:
        # Найти связанный OKR
        linked_okr = find_linked_okr(op_item, tactical_okrs)
        if linked_okr:
            # Найти связанную стратегическую цель
            linked_strategy = find_linked_strategy(linked_okr, strategy_goals)
            if linked_strategy:
                traceability_score += 1

    traceability = traceability_score / len(operational_items)

    # Синхронность метрик: движутся ли все уровни в одном направлении?
    strategy_direction = get_trend(strategy_goals.primary_metrics)
    tactical_direction = get_trend(tactical_okrs.key_results)
    operational_direction = get_trend(operational_metrics.kpis)

    alignment = cosine_similarity(
        [strategy_direction, tactical_direction, operational_direction]
    )

    iro = 0.6 * traceability + 0.4 * alignment
    return iro
```

### Глава 2. Закон Экономии в Менеджменте

#### 2.1 «Чёрный ящик» для Совещаний

Закон чёрного ящика Крюкова:
- ≤ 2 переходов между темами внутри одного действия
- ≤ 3 движений на одного противника
- 3:1 соотношение рук к шагам

В управлении это даёт **«Правила эффективного совещания»**:

```
ЗАКОН ЧЁРНОГО ЯЩИКА ДЛЯ СОВЕЩАНИЙ:

Правило 1 (≤ 2 переходов):
  За одно совещание — не более 3 разных тем.
  Каждый переход между темами стоит 10 минут разогрева.
  При 4+ темах — КПД совещания < 30%.

Правило 2 (≤ 3 решений):
  За одно совещание — не более 3 конкретных решений.
  Больше 3 решений: вероятность исполнения каждого < 60%.

Правило 3:1:
  На каждое стратегическое решение — 3 тактических шага.
  Без этого соотношения: стратегия «висит в воздухе».

Правило минимума (от ≤ 3 шагов):
  Решение не должно требовать более 3 промежуточных шагов.
  Если требует — разбить на подрешения.

ФОРМУЛА ИДЕАЛЬНОГО СОВЕЩАНИЯ:
  ≤ 3 темы × ≤ 3 решения × ≤ 3 шага каждое = ≤ 27 действий
  Время: ≤ 45 минут (не случайно это стандарт agile-команд)
```

#### 2.2 Закон Нечётности в Управлении Проектами

```
ЗАКОН НЕЧЁТНОСТИ В ПРОЕКТАХ:

Проект с нечётным числом этапов завершается «органично».
Проект с чётным числом этапов психологически «незавершён».

Правило:
  3 этапа: минимальный завершённый проект
    Иннициация → Исполнение → Завершение

  5 этапов: стандартный проект с «пиком»
    Старт → Анализ → КУЛЬМИНАЦИЯ → Разработка → Деплой

  7 этапов: сложный проект (максимум по закону памяти)
    Проект с 8+ этапами — нужна декомпозиция

Практика:
  Если у вас 4 спринта → добавьте «ретро-спринт» (5 = нечётное)
  Если у вас 6 этапов roadmap → объедините 2 смежных (5 = нечётное)
  Если у вас 10 шагов процесса → 9 или 11

Почему работает:
  Нечётная структура имеет «центр» → один главный этап
  Симметрия: N этапов до центра, N после → ощущение завершённости
```

#### 2.3 Пять Режимов Работы Команды

Система Крюкова описывает пять режимов движения (SCAN, SEQUENTIAL, ADAPTIVE, PRECISE, DUAL). В управлении они точно соответствуют режимам работы команды:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
РЕЖИМ 1: SCAN (Разведка)
  Характеристика: мониторинг, исследование, открытые вопросы
  Когда: начало квартала, кризис, выход на новый рынок
  Метрика успеха: quantity of insights, not quality of decisions
  Ошибка: застрять в Scan, не переходя к решениям

РЕЖИМ 2: SEQUENTIAL (Последовательное исполнение)
  Характеристика: чёткий plan, исполнение шаг-за-шагом
  Когда: известная задача, стабильная среда, найм, compliance
  Метрика: adherence to plan, velocity
  Ошибка: использовать Sequential в турбулентной среде

РЕЖИМ 3: ADAPTIVE (Адаптация)
  Характеристика: корректировка на ходу, итерации
  Когда: запуск продукта, pivot, реакция на конкурента
  Метрика: speed of adaptation, A/B test results
  Ошибка: бесконечная адаптация без commitment

РЕЖИМ 4: PRECISE (Точечное воздействие)
  Характеристика: фокус на одном критическом элементе
  Когда: production баг, переговоры, ключевое решение
  Метрика: precision, zero-defect rate
  Ошибка: Precise там, где нужна скорость

РЕЖИМ 5: DUAL (Параллелизм)
  Характеристика: одновременно несколько потоков
  Когда: scaling, expansion, M&A
  Метрика: parallel workstream progress
  Ошибка: Dual без достаточной команды → рассеивание ресурсов
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Диагностика текущего режима:**

```python
class OrganizationModeDetector:
    """
    Определить текущий режим работы организации/команды.
    Основа: анализ типа задач и поведения в решениях.
    """

    MODE_INDICATORS = {
        'SCAN': [
            'много открытых вопросов на встречах',
            'высокая частота внешних встреч и research',
            'решения откладываются «до уточнения»',
            'много новых входящих задач'
        ],
        'SEQUENTIAL': [
            'чёткий Gantt/roadmap',
            'высокая предсказуемость спринтов',
            'мало изменений в backlog',
            'высокая velocity'
        ],
        'ADAPTIVE': [
            'частые изменения приоритетов',
            'много A/B тестов и экспериментов',
            'короткие циклы решений (<1 нед)',
            'много «pivot» разговоров'
        ],
        'PRECISE': [
            'один главный фокус команды',
            'все ресурсы на одну задачу',
            'высокая интенсивность работы',
            'кризисный режим или critical feature'
        ],
        'DUAL': [
            'несколько независимых потоков',
            'разные команды без синхронизации',
            'расширение численности',
            'параллельные продукты'
        ]
    }

    def diagnose(self, team_data):
        """Определить режим по данным команды."""
        scores = {mode: 0 for mode in self.MODE_INDICATORS}

        for mode, indicators in self.MODE_INDICATORS.items():
            for indicator in indicators:
                if self._indicator_present(indicator, team_data):
                    scores[mode] += 1

        current_mode = max(scores, key=scores.get)
        confidence = scores[current_mode] / len(self.MODE_INDICATORS[current_mode])

        return {
            'mode': current_mode,
            'confidence': confidence,
            'scores': scores,
            'recommendation': self._get_recommendation(current_mode, team_data)
        }

    def _get_recommendation(self, current_mode, team_data):
        recommendations = {
            'SCAN': 'Установите дедлайн для перехода в SEQUENTIAL. '
                    'Scan не может длиться бесконечно.',
            'SEQUENTIAL': 'Отлично. Убедитесь, что среда стабильна. '
                         'При изменении — готовьтесь к ADAPTIVE.',
            'ADAPTIVE': 'Зафиксируйте commitment-точку. '
                        'Адаптация должна вести к решению, не к бесконечным итерациям.',
            'PRECISE': 'Оцените: длительность Precise-режима не должна превышать '
                      '2–3 недели. Затем — обязательно SCAN или SEQUENTIAL.',
            'DUAL': 'Синхронизируйте потоки еженедельно. '
                   'DUAL без синхронизации = разрыв петли.'
        }
        return recommendations.get(current_mode, '')
```

## ЧАСТЬ II. ЗВЕРИ КАК ОРГАНИЗАЦИОННЫЕ АРХЕТИПЫ

### Глава 3. Пять Организационных Культур

#### 3.1 Тигр-организация

```
ТИГР-ОРГАНИЗАЦИЯ: Amazon, Apple, Foxconn

Характеристики:
  Стратегия: прямая атака, агрессивное доминирование, лидерство по цене/объёму
  Культура: «Day 1 mindset» (Безос), высокая требовательность, быстрые решения
  Структура: иерархия + сильный центр принятия решений
  Слабость: уязвим для Змей (стартапов), которые «обходят» напрямую

Сигналы Тигра в действии:
  ✓ «Move fast and break things»
  ✓ JFDI (Just fucking do it)
  ✓ Data-driven, но финальное слово за лидером
  ✓ Поглощение конкурентов вместо партнёрства

Когда Тигр побеждает:
  + Объём и скорость — главные конкурентные преимущества
  + Рынок понятен, нужна только скорость исполнения

Когда Тигр проигрывает:
  - Высокая неопределённость рынка (Тигр не умеет «гнуться»)
  - Конкурент-Змея обходит с флангов через инновации
```

#### 3.2 Змея-организация

```
ЗМЕЯ-ОРГАНИЗАЦИЯ: Netflix, Spotify, Tesla

Характеристики:
  Стратегия: скорость, гибкость, disruption, «убить Тигра»
  Культура: автономия команд, «fail fast», high trust-high performance
  Структура: децентрализованная, federation of tribes
  Слабость: уязвима для Журавля (точность и качество)

Сигналы Змеи:
  ✓ Spotify «Tribe/Squad/Chapter» модель
  ✓ Netflix: «No rules rules» (Хейстингс)
  ✓ Частые pivots и эксперименты
  ✓ Инновация как core competency

Закон сильного справа:
  Змея побеждает Тигра: обходит через инновации и скорость
  Журавль побеждает Змею: выигрывает качеством и надёжностью
  Тигр побеждает Журавля: берёт объёмом и ценой
```

#### 3.3 Журавль-организация

```
ЖУРАВЛЬ-ОРГАНИЗАЦИЯ: NASA, Rolex, McKinsey, IDEO

Характеристики:
  Стратегия: совершенство, минимализм, «один выстрел»
  Культура: перфекционизм, глубокая экспертиза, slow decisions
  Структура: матричная, проектная, partnership-модель
  Слабость: медленная реакция на изменения рынка

Сигналы Журавля:
  ✓ «Хорошо сделанного достаточно» — но «хорошо» определяют они сами
  ✓ Огромные инвестиции в качество процесса
  ✓ Мало продуктов/услуг, но все — лучшие в классе
  ✓ Цена не является KPI

Применение в менеджменте:
  Журавль-режим нужен, когда:
  - Ошибка = катастрофа (авиация, медицина, ядерная)
  - Бренд = единственное конкурентное преимущество
  - Долгосрочные отношения с клиентами важнее краткосрочных продаж
```

#### 3.4 Медведь-организация

```
МЕДВЕДЬ-ОРГАНИЗАЦИЯ: Государственные структуры, большие банки, коммунальные службы

Характеристики:
  Стратегия: стабильность, предсказуемость, compliance
  Культура: процессы над инновацией, «так принято», low risk tolerance
  Структура: максимальная иерархия, формальные процедуры
  Слабость: почти ко всему — но Медведь незаменим в «стабильной» нише

Когда Медведь незаменим:
  + Регулируемые отрасли (банки, страховые, utilities)
  + Критическая инфраструктура (электросети, водоснабжение)
  + Процессы, где ошибка = нарушение закона

Как работать с Медведем:
  Змея-стартап vs. Медведь-регулятор: нужна «переводческая» структура —
  небольшая Журавль-команда (compliance team), которая «переводит»
  между скоростью Змеи и требованиями Медведя.
```

#### 3.5 Богомол-организация

```
БОГОМОЛ-ОРГАНИЗАЦИЯ: Консалтинговые boutiques, hedge funds, R&D labs

Характеристики:
  Стратегия: ожидание + точный удар в уязвимое место
  Культура: глубокое наблюдение, непропорциональный удар, минимум движений
  Структура: маленькая, плоская, высоко-компетентная
  Слабость: медленно реагирует на широкомасштабные вызовы

Сигналы Богомола:
  ✓ «Мы не берём все сделки — только те, где у нас edge»
  ✓ Высокий доход на одного сотрудника
  ✓ Долгий due diligence перед любым решением
  ✓ После «удара» — отход назад в позицию наблюдения

Богомол в продуктовой компании:
  Feature team: 95% времени наблюдает пользователей (Scan)
  5% времени: один точный фичер, который радикально меняет метрику
  Это противоположность Тигра — но иногда эффективнее.
```

### Глава 4. Циклическое Доминирование: Закон Сильного Справа

#### 4.1 Круг доминирования

```
ЦИКЛ ДОМИНИРОВАНИЯ ОРГАНИЗАЦИОННЫХ КУЛЬТУР:

        ЖУРАВЛЬ
       (качество)
          ▲
         / \
  МЕДВЕДЬ   БОГОМОЛ
 (надёжн.)  (точность)
       \       /
   ТИГР ←—— ЗМЕЯ
  (сила)  (скорость)

Направление стрелок = «побеждает»:
  Тигр → побеждает Журавля (объёмом и ценой)
  Змея → побеждает Тигра (инновациями и гибкостью)
  Журавль → побеждает Змею (качеством и надёжностью)
  Богомол → побеждает Медведя (точностью и асимметрией)
  Медведь → побеждает Змею (регуляцией и стабильностью)

Это не детерминизм — это вероятностное преимущество.
Умный руководитель диагностирует стиль конкурента →
выбирает контр-стиль → обеспечивает структурное преимущество.
```

#### 4.2 Практическое применение: стратегия vs. конкурента

```python
class CompetitiveStyleAnalyzer:
    """
    Анализ конкурентного стиля и выбор контр-стратегии.
    """

    DOMINANCE_CYCLE = {
        'tiger': 'snake',    # Змея побеждает Тигра
        'snake': 'crane',    # Журавль побеждает Змею
        'crane': 'tiger',    # Тигр побеждает Журавля
        'bear': 'mantis',    # Богомол побеждает Медведя
        'mantis': 'snake'    # Змея побеждает Богомола
    }

    def analyze_competitor(self, competitor_data):
        """
        Определить организационный стиль конкурента.
        """
        indicators = {
            'tiger': [
                competitor_data.get('market_share_growth', 0) > 0.15,
                competitor_data.get('price_competition', False),
                competitor_data.get('acquisition_rate', 0) > 2
            ],
            'snake': [
                competitor_data.get('product_iteration_speed', 0) > 4,  # фич/кв
                competitor_data.get('pivot_history', 0) > 1,
                competitor_data.get('team_autonomy_score', 0) > 0.7
            ],
            'crane': [
                competitor_data.get('premium_pricing', False),
                competitor_data.get('nps_score', 0) > 70,
                competitor_data.get('product_count', 10) < 5
            ],
            'bear': [
                competitor_data.get('regulatory_compliance_focus', False),
                competitor_data.get('decision_speed_days', 1) > 30,
                competitor_data.get('org_size', 0) > 10000
            ],
            'mantis': [
                competitor_data.get('revenue_per_employee', 0) > 500000,
                competitor_data.get('niche_focus', False),
                competitor_data.get('deal_selectivity', 0) > 0.8
            ]
        }

        scores = {
            style: sum(indicators[style]) / len(indicators[style])
            for style in indicators
        }

        competitor_style = max(scores, key=scores.get)
        counter_style = self.DOMINANCE_CYCLE[competitor_style]

        return {
            'competitor_style': competitor_style,
            'style_confidence': scores[competitor_style],
            'recommended_counter': counter_style,
            'strategic_advice': self._get_advice(competitor_style, counter_style)
        }

    def _get_advice(self, competitor, counter):
        advice = {
            ('tiger', 'snake'): (
                'Конкурент — Тигр: сила и объём. '
                'Ваш ответ: Змея — инновации и скорость. '
                'Не бейтесь с ним напрямую — обходите через новые сегменты.'
            ),
            ('snake', 'crane'): (
                'Конкурент — Змея: скорость и эксперименты. '
                'Ваш ответ: Журавль — качество и надёжность. '
                'Позиционируйтесь как «надёжная альтернатива экспериментальному хаосу».'
            ),
            ('crane', 'tiger'): (
                'Конкурент — Журавль: качество и премиум. '
                'Ваш ответ: Тигр — объём и цена. '
                'Democratize the market: то же качество, в 3× дешевле, в 5× быстрее.'
            ),
        }
        return advice.get((competitor, counter), 'Применяйте принцип сильного справа.')
```

## ЧАСТЬ III. ПЯТЬ УРОВНЕЙ ОРГАНИЗАЦИОННОГО МАСТЕРСТВА

### Глава 5. Эволюция Организации

#### 5.1 Пять стадий через призму Крюкова

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
УРОВЕНЬ 1 — СТАРТАП: «Язык задач»
  Думает: задачами и проблемами («решить проблему X пользователя»)
  Структура: плоская, все делают всё
  Метрики: выжить (runway), найти product-market fit
  Кризис-ключ: первые 10 платящих клиентов
  Переход: когда задач больше, чем один человек может удержать в голове

УРОВЕНЬ 2 — РАСТУЩАЯ КОМПАНИЯ: «Язык процессов»
  Думает: процессами и системами («как мы воспроизводим результат?»)
  Структура: функциональная, первые отделы
  Метрики: unit economics, CAC/LTV, team velocity
  Кризис-ключ: первый «системный сбой» — процесс сломался под нагрузкой
  Переход: когда процессы не успевают за ростом

УРОВЕНЬ 3 — ЗРЕЛАЯ КОМПАНИЯ: «Язык систем»
  Думает: взаимодействием систем («как части влияют друг на друга?»)
  Структура: матричная или divisional
  Метрики: market share, brand, employee NPS, operational excellence
  Кризис-ключ: первый серьёзный конкурентный вызов или дисрупция
  Переход: когда системы начинают бороться между собой (silos)

УРОВЕНЬ 4 — ЛИДЕР РЫНКА: «Язык категорий»
  Думает: рыночными категориями и трендами («мы создаём рынок»)
  Структура: platform + ecosystem
  Метрики: platform metrics, ecosystem health, category leadership
  Кризис-ключ: организация сама становится «рынком» для других
  Переход: когда категория начинает определяться через бренд компании

УРОВЕНЬ 5 — ЛЕГЕНДА ИНДУСТРИИ: «Язык ценностей»
  Думает: ценностями, миссией, цивилизационным вкладом
  Структура: культура как главный актив
  Метрики: impact, trust, long-term value creation
  Нет кризиса-ключа — Уровень 5 открыт через историческое испытание
  Примеры: Toyota (производственная система), Apple (Design as culture), LEGO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 5.2 Диагностика уровня организации

```python
class OrgLevelDiagnostic:
    """
    Диагностика уровня зрелости организации.
    """

    def diagnose(self, org_data):
        """
        Определить текущий уровень зрелости.
        """
        scores = {}

        # Уровень 1: Думает задачами?
        scores[1] = self._score_level_1(org_data)
        # Уровень 2: Думает процессами?
        scores[2] = self._score_level_2(org_data)
        # Уровень 3: Думает системами?
        scores[3] = self._score_level_3(org_data)
        # Уровень 4: Думает категориями?
        scores[4] = self._score_level_4(org_data)
        # Уровень 5: Думает ценностями?
        scores[5] = self._score_level_5(org_data)

        # Текущий уровень = наивысший с уверенностью > 0.6
        current_level = 1
        for level in range(5, 0, -1):
            if scores[level] > 0.6:
                current_level = level
                break

        return {
            'level': current_level,
            'scores': scores,
            'next_key': self._get_next_key(current_level),
            'strengths': self._get_strengths(current_level, org_data),
            'gaps': self._get_gaps(current_level, org_data)
        }

    def _score_level_1(self, org_data):
        """Стартап: задачи, выживание, product-market fit."""
        indicators = [
            org_data.get('has_pmf', False),
            org_data.get('team_size', 100) < 20,
            org_data.get('processes_documented', 0) < 3,
            org_data.get('primary_metric') == 'survival'
        ]
        return sum(indicators) / len(indicators)

    def _score_level_2(self, org_data):
        """Растущая компания: процессы, unit economics."""
        indicators = [
            org_data.get('has_documented_processes', False),
            org_data.get('ltv_cac_ratio', 0) > 3,
            org_data.get('team_size', 0) > 20,
            org_data.get('has_dedicated_functions', False)
        ]
        return sum(indicators) / len(indicators)

    def _score_level_3(self, org_data):
        """Зрелая компания: системы, сценарии."""
        indicators = [
            org_data.get('has_cross_functional_teams', False),
            org_data.get('market_share', 0) > 0.05,
            org_data.get('brand_recognition', 0) > 0.3,
            org_data.get('has_strategic_planning', False)
        ]
        return sum(indicators) / len(indicators)

    def _get_next_key(self, current_level):
        keys = {
            1: 'Первые 10 повторных платящих клиентов за стандартный продукт',
            2: 'Первый системный сбой при масштабировании — и его устранение',
            3: 'Первый серьёзный конкурентный вызов, требующий стратегического ответа',
            4: 'Компания становится стандартом для целой категории',
            5: 'Уже там. Вопрос — как удержать.'
        }
        return keys.get(current_level, '')
```

## ЧАСТЬ IV. РЕЗОНАНС КАК КОНКУРЕНТНОЕ ПРЕИМУЩЕСТВО

### Глава 6. Высокоэффективные Организации и Резонанс

#### 6.1 Признаки резонирующей организации

```
ПОРТРЕТ РЕЗОНИРУЮЩЕЙ ОРГАНИЗАЦИИ:

1. Скорость перевода стратегии в операции: < 2 недели
   (В нерезонирующей: 3–6 месяцев)

2. Сотрудники могут объяснить стратегию компании за 30 секунд
   (Тест: случайный сотрудник в лифте — объясни стратегию)

3. Операционные метрики движутся синхронно со стратегическими
   (NPS растёт → Retention растёт → Revenue растёт → Market share растёт)

4. Ошибки на оперативном уровне не «тонут» — быстро эскалируются
   (Петля замкнута: МВС → СВС → БВС за часы, не недели)

5. Культура = стратегия (язык в коридоре = язык в boardroom)
   (В нерезонирующей: «говорим одно, делаем другое»)
```

#### 6.2 Инструменты достижения резонанса

```python
class OrgResonanceBuilder:
    """
    Инструменты для достижения организационного резонанса.
    """

    def design_communication_rhythm(self, org_size, org_level):
        """
        Спроектировать ритм коммуникации между уровнями.
        Ключ: нечётные периоды, замкнутые петли.
        """
        if org_level == 1:  # Стартап
            return {
                'BVS_SVS_sync': 'ежедневно (все вместе)',
                'decision_loop': '24 часа',
                'retrospective': 'еженедельно'
            }
        elif org_level == 2:  # Растущая
            return {
                'BVS': 'ежеквартальное стратегическое совещание',
                'SVS': 'еженедельный тактический sync (OKR progress)',
                'MVS': 'ежедневный standup',
                'BVS_MVS_direct': 'ежемесячный All-Hands (всей компанией)',
                'decision_loop': '72 часа для тактических'
            }
        elif org_level >= 3:  # Зрелая+
            return {
                'BVS': 'ежеквартальные strategy sessions + Annual planning',
                'SVS': 'еженедельные бизнес-ревью (BRR)',
                'MVS': 'ежедневные standups + sprint reviews',
                'cross_level': 'ежемесячные Town Halls',
                'resonance_check': 'полугодовые Culture Surveys',
                'decision_loop': '1 неделя для тактических, 2 недели для стратегических'
            }

    def design_okr_cascade(self, company_strategy, levels=3):
        """
        Спроектировать каскад OKR для резонанса уровней.
        """
        cascade = {}

        # БВС: компания (1–3 цели)
        company_okrs = self._generate_company_okrs(company_strategy)
        cascade['BVS'] = company_okrs

        # СВС: отделы/команды (каждый OKR = 1–3 командных OKR)
        team_okrs = []
        for company_okr in company_okrs:
            team_contribution = self._decompose_to_team(company_okr)
            team_okrs.extend(team_contribution)
        cascade['SVS'] = team_okrs[:7]  # Закон памяти: ≤ 7

        # МВС: индивидуальные (каждый командный OKR = 1–3 задачи)
        individual_tasks = []
        for team_okr in cascade['SVS'][:3]:  # Фокус: берём топ-3
            tasks = self._decompose_to_individual(team_okr)
            individual_tasks.extend(tasks)
        cascade['MVS'] = individual_tasks[:9]  # Закон памяти: ≤ 9

        # Проверка резонанса: каждый уровень трассируется
        resonance_check = all(
            self._can_trace_up(mvs_task, cascade)
            for mvs_task in cascade['MVS']
        )

        return {
            'cascade': cascade,
            'resonance_check': resonance_check,
            'warning': None if resonance_check else
                      'Не все операционные задачи трассируются к стратегии!'
        }
```

## ЗАКЛЮЧЕНИЕ

**Ключевые выводы Тома 9:**

1. **Три сферы = три уровня управления.** МВС (операции, дни), СВС (тактика, кварталы), БВС (стратегия, годы). Каждый уровень имеет свой язык, ритм и метрику.

2. **Петля = контур обратной связи.** Здоровая организация = система замкнутых управленческих петель. LCI (Org) > 0.8 — здоровая культура решений.

3. **Резонанс = синхронизация уровней.** Организация в резонансе переводит стратегию в операции за дни, а не кварталы. ИРО > 0.8 — признак высокоэффективной организации.

4. **Пять режимов (SCAN/SEQUENTIAL/ADAPTIVE/PRECISE/DUAL)** описывают тип рабочей обстановки. Ключ менеджера — правильно диагностировать режим и адаптировать стиль управления.

5. **Пять организационных стилей (Тигр/Змея/Журавль/Медведь/Богомол)** — реальные конкурентные архетипы с циклическим доминированием. Правильный выбор контр-стиля = структурное конкурентное преимущество.

6. **Пять уровней зрелости** — эволюция «языка мышления» организации: задачи → процессы → системы → категории → ценности. Переход между уровнями происходит через кризис и преодоление.

7. **Закон нечётности** применим к совещаниям (≤ 3 темы), проектам (3, 5, 7 этапов) и OKR-каскадам. Нечётная структура создаёт естественную завершённость.
