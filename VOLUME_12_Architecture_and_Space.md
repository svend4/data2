## ПРЕДИСЛОВИЕ

Архитектура — это застывшее движение.

Когда Ле Корбюзье проектировал пандус виллы Савой, он проектировал **петлю** — траекторию, по которой тело поднимается с земли к небу через серию замкнутых витков. Когда японский архитектор проектирует «ма» (間) — паузу, пустоту между элементами — он проектирует **камуфляж**: то, чего нет, определяет то, что есть.

Великая архитектура — это застывший танец человека в пространстве. Плохая архитектура — это пространство, которое **мешает** движению: создаёт тупики вместо петель, монолитность вместо иерархии сфер, хаос вместо резонанса.

Данная книга исследует архитектуру через архетипы Крюкова — и предлагает **количественные метрики качества пространства**, основанные на принципах движения.

## ЧАСТЬ I. ПРОСТРАНСТВО КАК КИНЕМАТИЧЕСКАЯ СИСТЕМА

### Глава 1. Три Сферы Пространства

#### 1.1 Архитектурная иерархия сфер

Модель трёх сфер точно соответствует **проксемической иерархии** (теория Э. Холла о личном пространстве):

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
МВС — ИНТИМНОЕ ПРОСТРАНСТВО (0–45 см)
  Содержание: собственное тело, личные вещи
  В архитектуре: рабочий стол, кресло, кровать
  Масштаб: мебель, детали, текстуры
  Проектирование: эргономика, тактильные качества, масштаб руки

СВС — СОЦИАЛЬНОЕ ПРОСТРАНСТВО (45 см – 3.5 м)
  Содержание: пространство разговора, совместной деятельности
  В архитектуре: комната, офис, ресторанный столик
  Масштаб: помещение, окно, дверной проём
  Проектирование: пропорции, акустика, свет

БВС — ПУБЛИЧНОЕ ПРОСТРАНСТВО (3.5 м – ∞)
  Содержание: пространство города, природы, горизонта
  В архитектуре: площадь, фасад, ансамбль, пейзаж
  Масштаб: здание, квартал, городской контекст
  Проектирование: ориентиры, перспективы, городской ритм
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Закон трёх сфер в архитектуре:**

```
Здание «работает» тогда, когда все три сферы спроектированы
с вниманием к масштабу тела человека.

Патологии:
  Здание без МВС: Техника → Человек = инструмент, не цель
    (советские типовые офисы, безликие торговые центры)

  Здание без СВС: Нет помещений «для общения»
    (корпоративные open space без переговорных)
    → сотрудники не могут нормально взаимодействовать

  Здание без БВС: Нет связи с городом/природой
    (закрытые кварталы без выхода в публичное пространство)
    → жители теряют ориентацию и ощущение места
```

#### 1.2 Резонанс пространства: «Genius Loci»

«Genius loci» (дух места) — то неуловимое качество пространства, которое делает его «живым». Через архетипы Крюкова это формализуется как **пространственный резонанс**:

```
РЕЗОНАНС ПРОСТРАНСТВА = СИНХРОНИЗАЦИЯ ТРЁХ СФЕР

Условие: когда детали (МВС), помещения (СВС) и контекст (БВС)
говорят на одном «языке» — пространство резонирует.

Примеры пространственного резонанса:

Пантеон (Рим, 128 н.э.):
  МВС: мраморные панели, кассеты купола — ручной масштаб
  СВС: цилиндрический зал диаметром 43.4 м = точно = высота
  БВС: отношение к небу через окулус (отверстие в куполе)
  Резонанс: идеальная сфера вписана в цилиндр → ω_МВС = ω_СВС = ω_БВС

Японский чайный домик (Тясицу):
  МВС: текстура татами, грубость глины, зернистость дерева
  СВС: комната 4.5 татами (≈ 8 м²) — размер вытянутого тела
  БВС: связь с садом через нишу-токонома и окна
  Резонанс: три масштаба синхронизированы через принцип ваби-саби

«Плохой» пример — торговый центр 1990-х:
  МВС: пластик и нержавейка, нет тактильного качества
  СВС: атриум 30 м высотой, не соразмерный человеку
  БВС: закрытый, без окон, без связи с городом
  Антирезонанс: три сферы разорваны → пространство «мёртвое»
```

### Глава 2. Петля в Архитектуре

#### 2.1 Маршрут как петля

В системе Крюкова петля — это замкнутая траектория с обратной связью. В архитектуре это **маршрут** — путь, по которому тело движется через пространство.

```
ТИПОЛОГИЯ АРХИТЕКТУРНЫХ МАРШРУТОВ:

1. Тупиковый маршрут (прямая, не-петля):
   Вход → ... → тупик → возврат тем же путём
   LCI = 0.0 (нет замкнутости)
   Ощущение: клаустрофобия, тревога, потеря ориентации
   Примеры: коридоры без выхода, тупиковые дворы

2. Петлевой маршрут (замкнутый):
   Вход → ... → Выход = Вход (круговое движение)
   LCI = 1.0 (идеальная замкнутость)
   Ощущение: спокойствие, ориентация, уверенность
   Примеры: клуатры монастырей, японские сады, музейные анфилады

3. Спиральный маршрут (петля с нарастанием):
   Вход → (петля на уровне 1) → (петля на уровне 2) → ... → Вершина
   LCI = 0.7–0.9 (квазизамкнутый)
   Ощущение: нарастание, кульминация, раскрытие
   Примеры: рампа Гуггенхайм, лестничная башня, Пирамида Маслоу в пространстве

4. Восьмёрочный маршрут (двойная петля):
   Две пространственные петли, соединённые перекрёстком
   LCI = 0.8
   Ощущение: богатство выбора, неожиданность открытий
   Примеры: некоторые японские сады (кайюсики), торговые ряды
```

#### 2.2 LCI пространства: метрика качества маршрута

```python
import numpy as np
from scipy.spatial import ConvexHull

class ArchitecturalLCIAnalyzer:
    """
    Анализатор качества архитектурного пространства
    через Loop Closure Index маршрутов.
    """

    def analyze_floorplan(self, walls, doorways, scale_m_per_px=0.05):
        """
        Анализ плана этажа: все возможные маршруты и их LCI.

        walls: список отрезков [(x1,y1,x2,y2), ...]
        doorways: список точек соединения помещений [(x,y), ...]
        scale: масштаб (метры на пиксель)
        """
        # Построить граф помещений
        room_graph = self._build_room_graph(walls, doorways)

        # Найти все циклы в графе (возможные петлевые маршруты)
        cycles = self._find_all_cycles(room_graph)

        results = []
        for cycle in cycles:
            # Координаты точек цикла
            points = [doorways[i] for i in cycle]
            lci = self._compute_spatial_lci(points, scale_m_per_px)

            results.append({
                'cycle': cycle,
                'length_m': self._path_length(points, scale_m_per_px),
                'lci': round(lci, 3),
                'quality': self._classify_lci(lci)
            })

        # Общий LCI здания = средний LCI всех найденных петель
        if results:
            building_lci = sum(r['lci'] for r in results) / len(results)
        else:
            building_lci = 0.0  # Нет петель — тупиковая планировка

        return {
            'building_lci': round(building_lci, 3),
            'cycles_found': len(cycles),
            'cycles_detail': results,
            'recommendation': self._recommend(building_lci, len(cycles))
        }

    def _compute_spatial_lci(self, points_px, scale):
        """LCI пространственного маршрута."""
        pts = np.array(points_px, dtype=float) * scale  # Конвертируем в метры
        if len(pts) < 3:
            return 0.0
        try:
            hull = ConvexHull(pts)
            enclosed_area = hull.volume  # В 2D это площадь (м²)
        except Exception:
            return 0.0

        x_range = pts[:, 0].max() - pts[:, 0].min()
        y_range = pts[:, 1].max() - pts[:, 1].min()
        bbox_area = x_range * y_range

        return min(1.0, enclosed_area / bbox_area) if bbox_area > 0 else 0.0

    def _path_length(self, points_px, scale):
        """Длина маршрута в метрах."""
        total = 0.0
        pts = np.array(points_px, dtype=float) * scale
        for i in range(1, len(pts)):
            total += np.linalg.norm(pts[i] - pts[i-1])
        # Замкнуть петлю
        if len(pts) > 1:
            total += np.linalg.norm(pts[0] - pts[-1])
        return round(total, 1)

    def _classify_lci(self, lci):
        if lci >= 0.8:
            return 'ОТЛИЧНАЯ ПЕТЛЯ — комфортный маршрут'
        elif lci >= 0.6:
            return 'ХОРОШАЯ ПЕТЛЯ — достаточно комфортно'
        elif lci >= 0.4:
            return 'СЛАБАЯ ПЕТЛЯ — маршрут неудобен'
        elif lci > 0:
            return 'ПСЕВДО-ПЕТЛЯ — фактически тупик'
        else:
            return 'НЕТ ПЕТЛИ — тупиковый план'

    def _recommend(self, building_lci, n_cycles):
        if building_lci >= 0.75 and n_cycles >= 3:
            return 'Планировка отличная: богатая петлевая структура.'
        elif building_lci >= 0.6:
            return 'Планировка удовлетворительная. Добавить 1-2 соединительных прохода.'
        elif n_cycles == 0:
            return 'КРИТИЧНО: нет ни одной замкнутой петли. Перепроектировать план.'
        else:
            return 'Планировка слабая. Открыть тупики, создать петлевые маршруты.'

    def _build_room_graph(self, walls, doorways):
        """Упрощённое построение графа смежности помещений."""
        # В реальной реализации: геометрический анализ стен и дверей
        # Здесь — заглушка для демонстрации архитектуры системы
        graph = {i: [] for i in range(len(doorways))}
        for i, d1 in enumerate(doorways):
            for j, d2 in enumerate(doorways):
                if i != j:
                    dist = np.linalg.norm(np.array(d1) - np.array(d2))
                    if dist < 100:  # Пороговое расстояние (пиксели)
                        graph[i].append(j)
        return graph

    def _find_all_cycles(self, graph, max_length=8):
        """Найти все циклы в графе помещений."""
        cycles = []
        nodes = list(graph.keys())

        def dfs(start, current, path, visited):
            if len(path) > max_length:
                return
            for neighbor in graph.get(current, []):
                if neighbor == start and len(path) > 2:
                    cycles.append(path[:])
                elif neighbor not in visited:
                    visited.add(neighbor)
                    path.append(neighbor)
                    dfs(start, neighbor, path, visited)
                    path.pop()
                    visited.remove(neighbor)

        for node in nodes:
            dfs(node, node, [node], {node})

        # Убрать дубликаты циклов
        unique = []
        seen = set()
        for cycle in cycles:
            key = tuple(sorted(cycle))
            if key not in seen:
                seen.add(key)
                unique.append(cycle)

        return unique
```

### Глава 3. Закон Нечётности в Пространстве

#### 3.1 Пропорции и нечётность

```
НЕЧЁТНОСТЬ В АРХИТЕКТУРНЫХ ПРОПОРЦИЯХ:

Золотое сечение (φ = 1.618...):
  Фибоначчи: 1, 1, 2, 3, 5, 8, 13, 21...
  Нечётные: 1, 3, 5, 13, 21 — «золотые» пропорции
  Чётные: 2, 8 — «устойчивые» пропорции

  Парфенон: 8×17 колонн → оба нечётны по-отдельности!
  (8 = 2³, но 17 — нечётно и простое → «динамика»)

Классические ордера:
  Колонны по фасаду: нечётное лучше чётного
    5 колонн: акцент на центральной → вход очевиден
    6 колонн: два варианта входа → неопределённость
    7 колонн: ≥ 5 — богатый ритм с центром
    Примеры: Эрехтейон (6 — но две трёхколонные группы)

Окна:
  3, 5, 7 окон на фасаде — «живой» ритм
  4, 6, 8 — «спокойный», но менее выразительный
  Вывод: нечётное — динамика, чётное — статика

Ступени:
  Лестница с нечётным числом ступеней:
  Начинаем и заканчиваем одной ногой → ощущение завершённости
  Чётное число: заканчиваем другой ногой → «незавершённость»
  (Это прямое применение закона нечётности к шагам!)
```

#### 3.2 Иерархия масштабов и нечётность

```
НЕЧЁТНЫЕ МАСШТАБНЫЕ ПЕРЕХОДЫ В АРХИТЕКТУРЕ:

Городской масштаб: 3 уровня (нечётно)
  1. Улица — ширина 10–30 м
  2. Квартал — 100–300 м
  3. Район — 1–3 км

Здание: 3 зоны (нечётно)
  1. Цоколь (земля) — визуально тяжёлый
  2. Тело — нейтральный ритм
  3. Карниз/атика — визуально лёгкий

Фасад: 3 части по горизонтали (нечётно)
  1. Левая бухта
  2. Центр (вход/акцент)
  3. Правая бухта

Помещение: 5 зон (нечётно)
  1. Вход
  2. Переход
  3. Центр (рабочая зона)
  4. Переход
  5. Выход/окно

Проблема большинства советских панельных домов:
  → Фасад: 6, 8, 12 секций (чётно) → монотонность
  → Квартира: 4 комнаты (чётно) → нет центра
  → Лестничные марши: 9 ступеней (нечётно!) → хорошо!
```

### Глава 4. Камуфляж/Угроза: Пространственная Двойственность

#### 4.1 Японское «Ма» как архитектурный камуфляж

```
«МА» (間) — ЯПОНСКАЯ КОНЦЕПЦИЯ ПРОСТРАНСТВЕННОЙ ПАУЗЫ:

Определение:
  «Ма» — промежуток, пауза, пустота между элементами
  Это не «ничто» — это активная пустота, несущая смысл

Соответствие системе Крюкова:
  Явная форма (угроза) = стены, колонны, перекрытия — то, что видно
  «Ма» (камуфляж) = проёмы, дворы, паузы — то, чего нет, но что определяет всё

Примеры «ма»:
  Токонома (ниша в чайном домике):
    Пустая ниша → всё внимание на один предмет
    Пустота = «камуфляж» → предмет «говорит» громче на фоне тишины

  Японский сад кaресансуй (сухой):
    Камни в белом гравии
    Гравий = «ма» (пустота) → камни = «угроза» (присутствие)
    Созерцание: сначала видишь камни, потом — пространство между ними

  Храм Иссэ (Япония):
    Главное здание окружено несколькими рядами пустых заборов
    Дойти до него = пройти через нарастающую «ма»
    Смысл: пустота — это подготовка к присутствию

Архитектурный принцип:
  Пространство «дышит» когда угроза (форма) и камуфляж (пустота)
  чередуются ритмично — как вдох и выдох.
```

#### 4.2 Свет и тень как камуфляж/угроза

```python
class LightShadowAnalyzer:
    """
    Анализ распределения света и тени в пространстве
    через принцип Камуфляж/Угроза.

    Свет = «угроза» (явное присутствие)
    Тень = «камуфляж» (скрытое, намекающее)
    """

    def analyze_light_distribution(self, luminance_map):
        """
        Анализ карты яркости помещения (2D массив значений 0–1).
        Вычисляет: LCI света, резонанс, баланс угроза/камуфляж.

        luminance_map: np.array(H, W), значения 0 (темно) — 1 (ярко)
        """
        import numpy as np

        # LCI: насколько «петлеобразно» распределён свет?
        bright_pixels = luminance_map > 0.7  # Зоны света (угроза)
        dark_pixels = luminance_map < 0.3    # Зоны тени (камуфляж)

        bright_ratio = bright_pixels.mean()
        dark_ratio = dark_pixels.mean()
        mid_ratio = 1.0 - bright_ratio - dark_ratio

        # Идеальный баланс: 1/3 — 1/3 — 1/3 (свет, переход, тень)
        # Это нечётное трёхчастное деление!
        balance_score = 1.0 - (
            abs(bright_ratio - 0.333) +
            abs(dark_ratio - 0.333) +
            abs(mid_ratio - 0.333)
        )

        # Контрастность: перепад между светлыми и тёмными зонами
        contrast = luminance_map.std()

        # Периодичность: насколько ритмично чередуются свет и тень
        row_means = luminance_map.mean(axis=1)
        fft_vals = np.abs(np.fft.rfft(row_means))
        dominant_spatial_freq = np.argmax(fft_vals[1:]) + 1
        # Нечётная частота = ритмичный свет (не монотонный)
        rhythm_score = 1.0 if dominant_spatial_freq % 2 == 1 else 0.7

        # Spatial LCI: насколько «замкнуты» световые зоны
        bright_coords = np.argwhere(bright_pixels)
        if len(bright_coords) >= 4:
            try:
                from scipy.spatial import ConvexHull
                hull = ConvexHull(bright_coords)
                hull_area = hull.volume
                bbox_area = (bright_coords[:, 0].max() - bright_coords[:, 0].min()) * \
                            (bright_coords[:, 1].max() - bright_coords[:, 1].min())
                light_lci = min(1.0, hull_area / bbox_area) if bbox_area > 0 else 0.0
            except Exception:
                light_lci = 0.5
        else:
            light_lci = 0.0

        return {
            'light_ratio': round(bright_ratio, 3),
            'shadow_ratio': round(dark_ratio, 3),
            'transition_ratio': round(mid_ratio, 3),
            'balance_score': round(balance_score, 3),
            'contrast': round(contrast, 3),
            'rhythm_score': round(rhythm_score, 3),
            'light_lci': round(light_lci, 3),
            'quality': self._classify_light(balance_score, contrast, light_lci),
        }

    def _classify_light(self, balance, contrast, lci):
        if balance > 0.7 and contrast > 0.2 and lci > 0.6:
            return 'РЕЗОНАНС СВЕТА — живое, выразительное освещение (ма)'
        elif balance > 0.5:
            return 'ХОРОШИЙ БАЛАНС — достаточная выразительность'
        elif contrast < 0.1:
            return 'ПЛОСКОЕ ОСВЕЩЕНИЕ — нет диалога свет/тень'
        else:
            return 'НЕСБАЛАНСИРОВАННОЕ — пересветлено или темно'
```

### Глава 6. Городской Резонанс

#### 6.1 Город как организм трёх сфер

```
ГОРОД КАК КИНЕМАТИЧЕСКАЯ СИСТЕМА:

МВС города: тротуар, витрина, скамейка
  Масштаб пешехода (0.5–5 м)
  Определяет: «живость» улицы (Джейн Джейкобс: «eyes on the street»)
  Патология: стеклянные глухие фасады без деталей → мёртвая улица

СВС города: квартал, площадь, бульвар
  Масштаб района (50–500 м)
  Определяет: идентичность места, «обитаемость»
  Патология: сверхкрупные кварталы → нет человеческого масштаба

БВС города: силуэт, районы, ландшафт
  Масштаб горизонта (500 м – ∞)
  Определяет: читаемость города как целого
  Патология: башни без связи с улицей → разрыв БВС-МВС
```

#### 6.2 Петля как основа городского движения

```
ТЕОРИЯ ПЕТЕЛЬ В УРБАНИСТИКЕ:

Исследование Кевина Линча («Образ города», 1960):
  Люди воспринимают город через:
  - Пути (paths): маршруты движения
  - Узлы (nodes): точки концентрации
  - Ориентиры (landmarks): визуальные якоря

  Система Крюкова: Пути = петли, Узлы = точки пересечения петель,
  Ориентиры = «якоря» для БВС-ориентации.

LCI района:
  Высокий LCI (> 0.7): много замкнутых пешеходных маршрутов
    → жители гуляют, встречают соседей, знают место
    Примеры: Старый Арбат, Марэ (Париж), Сохо (Лондон)

  Низкий LCI (< 0.4): мало петель, много тупиков
    → люди ездят на машинах, не знают соседей
    Примеры: типовые советские спальные районы,
              американские suburbs без тротуаров

Практический вывод:
  Создание города с LCI > 0.7 = создание пешеходного, живого города.
  Это не эстетика. Это инфраструктурный показатель качества жизни.
```

### Глава 7. Алгоритмическое Проектирование на Основе Архетипов

```python
class ArchetypeBasedLayoutGenerator:
    """
    Генератор планировочных решений на основе архетипов Крюкова.
    Создаёт планы помещений с высоким LCI и резонансом трёх сфер.
    """

    def __init__(self, width_m, height_m, resolution=0.5):
        """
        width_m, height_m: размеры пространства в метрах
        resolution: размер ячейки сетки в метрах
        """
        self.width = width_m
        self.height = height_m
        self.res = resolution
        self.grid_w = int(width_m / resolution)
        self.grid_h = int(height_m / resolution)

    def generate_loop_plan(self, n_rooms=5, target_lci=0.75):
        """
        Генерировать план с петлевой структурой маршрутов.

        n_rooms: число помещений (нечётное — закон нечётности!)
        target_lci: целевой LCI
        """
        if n_rooms % 2 == 0:
            n_rooms += 1  # Принудительно нечётное

        best_plan = None
        best_lci = 0.0

        for attempt in range(100):  # Случайный поиск + оценка
            plan = self._random_plan(n_rooms)
            lci = self._estimate_plan_lci(plan)

            if lci > best_lci:
                best_lci = lci
                best_plan = plan

            if best_lci >= target_lci:
                break

        return {
            'plan': best_plan,
            'lci': round(best_lci, 3),
            'n_rooms': n_rooms,
            'achieved_target': best_lci >= target_lci
        }

    def _random_plan(self, n_rooms):
        """Генерировать случайный план с n помещениями."""
        import random
        rooms = []
        for i in range(n_rooms):
            w = random.randint(3, 8)   # 1.5–4 м
            h = random.randint(3, 8)   # 1.5–4 м
            x = random.randint(0, self.grid_w - w)
            y = random.randint(0, self.grid_h - h)
            rooms.append({'id': i, 'x': x, 'y': y, 'w': w, 'h': h})

        # Генерировать связи (двери) между соседними помещениями
        connections = []
        for i, r1 in enumerate(rooms):
            for j, r2 in enumerate(rooms):
                if i < j and self._are_adjacent(r1, r2):
                    connections.append((i, j))

        return {'rooms': rooms, 'connections': connections}

    def _are_adjacent(self, r1, r2, gap=1):
        """Проверить, соседние ли два помещения."""
        # Перекрытие по X
        x_overlap = (r1['x'] < r2['x'] + r2['w'] + gap and
                     r2['x'] < r1['x'] + r1['w'] + gap)
        # Перекрытие по Y
        y_overlap = (r1['y'] < r2['y'] + r2['h'] + gap and
                     r2['y'] < r1['y'] + r1['h'] + gap)
        return x_overlap and y_overlap

    def _estimate_plan_lci(self, plan):
        """
        Оценить LCI плана через граф связей.
        Больше петель в графе = выше LCI.
        """
        rooms = plan['rooms']
        connections = plan['connections']

        if not connections:
            return 0.0

        # Построить матрицу смежности
        n = len(rooms)
        adj = [[0]*n for _ in range(n)]
        for i, j in connections:
            adj[i][j] = 1
            adj[j][i] = 1

        # Считаем треугольники (минимальные петли)
        triangles = 0
        for i in range(n):
            for j in range(i+1, n):
                if adj[i][j]:
                    for k in range(j+1, n):
                        if adj[j][k] and adj[i][k]:
                            triangles += 1

        # LCI ~ количество замкнутых подграфов / общее число рёбер
        max_triangles = n * (n-1) * (n-2) / 6
        return min(1.0, triangles / max_triangles) if max_triangles > 0 else 0.0

    def apply_three_sphere_zoning(self, plan):
        """
        Назначить зоны МВС/СВС/БВС помещениям плана.
        МВС = маленькие помещения (детали, санузел, кладовая)
        СВС = средние (спальня, кабинет)
        БВС = большие (гостиная, зал, двор)
        """
        for room in plan['rooms']:
            area = room['w'] * room['h'] * (self.res ** 2)  # м²
            if area < 6:
                room['sphere'] = 'MVS'
                room['type'] = 'storage/wc'
            elif area < 15:
                room['sphere'] = 'SVS'
                room['type'] = 'bedroom/office'
            else:
                room['sphere'] = 'BVS'
                room['type'] = 'living/hall'

        # Резонанс зонирования: все три типа должны присутствовать
        spheres_present = set(r['sphere'] for r in plan['rooms'])
        plan['sphere_resonance'] = len(spheres_present) == 3

        return plan
```

## ЗАКЛЮЧЕНИЕ

**Ключевые выводы Книги 12:**

1. **Три сферы пространства** = МВС (0–45 см, тактильное, интимное), СВС (45 см – 3.5 м, социальное, помещение), БВС (3.5 м – ∞, публичное, городское). Резонанс трёх сфер = «Genius Loci».

2. **Маршрут как петля**: LCI пространства измеряет степень «петлевости» планировочного решения. LCI < 0.4 — тупиковая планировка. LCI > 0.75 — живой, комфортный план.

3. **Нечётность в архитектуре**: нечётное число колонн (3, 5, 7), окон, ступеней, фасадных секций создаёт «живой» ритм. Нечётное число ступеней — начинаем и заканчиваем той же ногой.

4. **«Ма» (японская пустота) = Камуфляж**: архитектурная пауза активна и смыслонесуща. Пространство «дышит» через чередование присутствия и отсутствия.

5. **LCI района**: количественный показатель «пешеходности» городской ткани. Высокий LCI — живой, ходячий город. Низкий LCI — автомобильные спальники.

6. **`ArchetypeBasedLayoutGenerator`**: алгоритмический генератор планов с нечётным числом помещений и целевым LCI. Возможно применение в generative design.
